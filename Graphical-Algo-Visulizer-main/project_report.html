1. Project Overview & System Architecture

The Graphical Algorithm Visualizer is a high-performance educational desktop application developed in C. It bridges theoretical computer graphics mathematics with real-time, interactive raster graphics animations.

Unlike standard static plotting software, this visualizer demonstrates how the CPU decides which pixel to illuminate on each discrete iteration, providing side-by-side mathematical telemetry (step counter, decision parameter updates, candidate pixel coordinates, and geometric status).

System Highlights:
  • Native Windows Compilation: Uses MinGW-w64 with the 64-bit WinBGIm port, compiling down to a standalone native binary without external runtime bloat.
  • Split-Screen Layout: Left viewport ($800 \times 700$ px) hosts the Cartesian mathematical plane; Right viewport ($200 \times 700$ px) renders a real-time telemetry HUD displaying equations and step-by-step decision metrics.
  • Interactive Speed Control: Configurable frame pacing (Slow: 200ms, Medium: 50ms, Fast: 10ms) allows students to observe individual step decisions or run full benchmarks.

2. Coordinate Mapping & Negative Point Handling

Computer screen memory is conventionally addressed with $(0,0)$ at the top-left corner, where $Y$ increases downwards. Standard mathematical graphs, however, place $(0,0)$ in the center with $+Y$ pointing upward. The visualizer bridges this using mathematical transformation functions:

// Coordinate Mapping Equations
int toScreenX(int x) { 
    return ORIGIN_X + x;       // ORIGIN_X = 400
}
int toScreenY(int y) { 
    return ORIGIN_Y - y;       // ORIGIN_Y = 350 (Inverts mathematical Y to screen Y)
}

Negative Coordinate & Input Protection:

  • Minus-Sign Input Handling: The custom GUI input engine (getGraphicalInput) supports typing the minus sign (-) at the start of any coordinate or toggling it dynamically, enabling full 4-quadrant inputs.
  • Panel Boundary Guard: Pixel plotting verifies that $2 \le x_{screen} \le 798$ and $2 \le y_{screen} \le 698$, guaranteeing that extreme or negative coordinates never bleed into the right-hand Info Panel.

3. Algorithm 1: DDA (Digital Differential Analyzer) Line Algorithm

The DDA algorithm calculates pixel locations along a straight line by taking unit steps in one coordinate and calculating corresponding fractional increments in the other based on the differential equation $\frac{dy}{dx} = m$.

Mathematical Formula

  1. Compute span differences: $\Delta x = x_2 - x_1$ and $\Delta y = y_2 - y_1$.
  2. Determine step count: $steps = \max(|\Delta x|, |\Delta y|)$.
  3. Calculate unit increments: $$x_{inc} = \frac{\Delta x}{steps}, \quad y_{inc} = \frac{\Delta y}{steps}$$
  4. Plot successive pixels iteratively: $(x_{k+1}, y_{k+1}) = (x_k + x_{inc}, y_k + y_{inc})$ rounded to nearest integer: $$x_{pixel} = \text{round}(x), \quad y_{pixel} = \text{round}(y)$$
Evaluation: DDA is mathematically straightforward, but requires floating-point additions and a round() operation at every pixel, making it computationally slower in pure software rasterizers compared to integer-only algorithms.

4. Algorithm 2: Bresenham's Line Algorithm

Bresenham's algorithm eliminates all floating-point math and divisions by reformulating line drawing into purely integer additions, subtractions, and bitwise shifts.

Mathematical Derivation

For a line with gentle positive slope ($0 < m \le 1$), the major axis is $X$. At each step, $x$ increments by 1, and the algorithm decides between the East pixel $(x_k+1, y_k)$ and the North-East pixel $(x_k+1, y_k+1)$.

The decision parameter $p_k$ is derived from the difference between the vertical distances $d_1$ and $d_2$ from the true mathematical line to the lower and upper pixel centers:

Decision Condition Selected Pixel Next Decision Parameter Update
Initial Step: $k = 0$ $(x_1, y_1)$ $p_0 = 2\Delta y - \Delta x$
If $p_k < 0$: Midpoint is above the true line Choose East: $(x_k + 1, y_k)$ $p_{k+1} = p_k + 2\Delta y$
If $p_k \ge 0$: Midpoint is on or below the true line Choose North-East: $(x_k + 1, y_k + 1)$ $p_{k+1} = p_k + 2\Delta y - 2\Delta x$

5. Algorithm 3: Midpoint Line Algorithm (All 6 Slope Conditions)

The Midpoint Line Drawing Algorithm is based on evaluating the line's implicit equation $F(x, y) = ax + by + c = 0$ (where $a = \Delta y, b = -\Delta x, c = x_1 y_2 - x_2 y_1$) at the exact midpoint $M$ between candidate pixels.

The visualizer comprehensively satisfies all 6 geometric slope conditions:

Condition 1 Gentle Positive Slope ($0 < m \le 1$)

Step: $x$ increments by $+1$. Candidate pixels are East $(x+1, y)$ and North-East $(x+1, y+1)$.

Initial: $d_0 = 2\Delta y - \Delta x$

• If $d \le 0$: Choose East, $d = d + 2\Delta y$
• If $d > 0$: Choose North-East, $y = y + 1$, $d = d + 2(\Delta y - \Delta x)$

Condition 2 Gentle Negative Slope ($-1 \le m < 0$)

Step: $x$ increments by $+1$. Candidate pixels are East $(x+1, y)$ and South-East $(x+1, y-1)$.

Initial: $d_0 = 2|\Delta y| - \Delta x$

• If $d \le 0$: Choose East, $d = d + 2|\Delta y|$
• If $d > 0$: Choose South-East, $y = y - 1$, $d = d + 2(|\Delta y| - \Delta x)$

Condition 3 Steep Positive Slope ($m > 1$)

Step: Major axis is $Y$. $y$ increments by $+1$. Candidate pixels are North $(x, y+1)$ and North-East $(x+1, y+1)$.

Initial: $d_0 = 2\Delta x - \Delta y$

• If $d \le 0$: Choose North, $d = d + 2\Delta x$
• If $d > 0$: Choose North-East, $x = x + 1$, $d = d + 2(\Delta x - \Delta y)$

Condition 4 Steep Negative Slope ($m < -1$)

Step: Major axis is $Y$. $y$ decrements by $-1$. Candidate pixels are South $(x, y-1)$ and South-East $(x+1, y-1)$.

Initial: $d_0 = 2\Delta x - |\Delta y|$

• If $d \le 0$: Choose South, $d = d + 2\Delta x$
• If $d > 0$: Choose South-East, $x = x + 1$, $d = d + 2(\Delta x - |\Delta y|)$

Condition 5 Horizontal Line ($m = 0, \Delta y = 0$)

Direct stepping along $X$ axis from $x_1$ to $x_2$ with $y$ held constant. Zero decision parameter evaluation needed.

Condition 6 Vertical Line ($\Delta x = 0$)

Direct stepping along $Y$ axis from $y_1$ to $y_2$ with $x$ held constant. Avoids division-by-zero slope errors completely.

6. Algorithm 4: Midpoint Circle Drawing Algorithm (8-Way Symmetry)

The Midpoint Circle Algorithm evaluates the implicit circle equation $F(x, y) = x^2 + y^2 - R^2 = 0$. By taking advantage of the circle's eight-fold symmetry, the algorithm only computes pixel coordinates for a single octant ($x \le y$, where the tangent slope varies from $0$ to $-1$), reflecting every point across all 8 octants simultaneously.

8-Way Symmetric Reflections

For any point $(x, y)$ computed on the circle perimeter relative to center $(x_c, y_c)$, 8 pixels are plotted at once:

plotCirclePoints(xc, yc, x, y):
  Plot(xc + x, yc + y)    Plot(xc - x, yc + y)
  Plot(xc + x, yc - y)    Plot(xc - x, yc - y)
  Plot(xc + y, yc + x)    Plot(xc - y, yc + x)
  Plot(xc + y, yc - x)    Plot(xc - y, yc - x)

Decision Parameter Derivation

  1. Starting point at top of circle: $(x_0, y_0) = (0, R)$.
  2. Midpoint between candidate pixels $E(1, R)$ and $SE(1, R - 1)$ is $M\left(1, R - \frac{1}{2}\right)$.
  3. Evaluate implicit function at $M$: $$d_0 = F\left(1, R - \frac{1}{2}\right) = 1^2 + \left(R - \frac{1}{2}\right)^2 - R^2 = 1 + R^2 - R + \frac{1}{4} - R^2 = \frac{5}{4} - R$$
  4. Since $R$ is an integer, rounding $\frac{5}{4}$ gives the standard integer initialization: $$\mathbf{d_0 = 1 - R}$$
Decision Parameter Test Pixel Selected Coordinate Update Parameter Increment
If $d_k < 0$: Midpoint inside circle Choose East $x = x + 1, \quad y = y$ $d_{k+1} = d_k + 2x + 3$
If $d_k \ge 0$: Midpoint outside or on circle Choose South-East $x = x + 1, \quad y = y - 1$ $d_{k+1} = d_k + 2(x - y) + 5$

7. Algorithm 5: Cohen-Sutherland Line Clipping Algorithm

The Cohen-Sutherland algorithm divides 2D space into 9 regions relative to a rectangular clipping window $[X_{min}, X_{max}] \times [Y_{min}, Y_{max}]$. Every point is assigned a 4-bit Outcode: [TOP, BOTTOM, RIGHT, LEFT].

1001 (Top-Left) 1000 (Top-Center) 1010 (Top-Right)
0001 (Left) 0000 (CLIP WINDOW) 0010 (Right)
0101 (Bottom-Left) 0100 (Bottom-Center) 0110 (Bottom-Right)

Evaluation Rules:

  • Trivial Accept: (outcode1 | outcode2) == 0. Both endpoints are inside the window; the entire line is visible.
  • Trivial Reject: (outcode1 & outcode2) != 0. Both endpoints share an outside half-plane; the line lies entirely outside the window.
  • Clipping Required: If neither condition holds, pick the endpoint outside the window, find its intersection with the corresponding window boundary, and re-evaluate until trivial accept or reject is reached.

8. Algorithm 6: Sutherland-Hodgman Polygon Clipping Algorithm

The Sutherland-Hodgman algorithm clips an arbitrary polygon against a convex clipping window. It processes the entire polygon iteratively through a 4-Stage Boundary Pipeline:

Pipeline Execution Order:
Input Polygon  ➔  1. Left Edge ($x \ge X_{min}$)  ➔  2. Right Edge ($x \le X_{max}$)  ➔  3. Bottom Edge ($y \ge Y_{min}$)  ➔  4. Top Edge ($y \le Y_{max}$)  ➔  Final Clipped Polygon

All 4 Clipping Conditions Satisfied

At each boundary stage, the algorithm traverses every directed polygon edge from vertex $V_1$ to vertex $V_2$ and tests which of the four conditions is triggered:

Case 1 IN ➔ IN (Both Inside)

Both vertices $V_1$ and $V_2$ lie inside the clipping boundary.

Action: Save vertex $V_2$ to the output list.

outPoly[outCount++] = V2;
Case 2 IN ➔ OUT (Exiting Boundary)

Vertex $V_1$ is inside, but vertex $V_2$ is outside the boundary.

Action: Calculate intersection point $V'$ and save $V'$ to output.

V' = intersectEdge(V1, V2); outPoly[outCount++] = V';
Case 3 OUT ➔ OUT (Both Outside)

Both vertices $V_1$ and $V_2$ lie outside the clipping boundary.

Action: Discard both vertices; nothing is saved to the output list.

// No vertices saved to output list
Case 4 OUT ➔ IN (Entering Boundary)

Vertex $V_1$ is outside, but vertex $V_2$ is inside the boundary.

Action: Calculate intersection $V'$, save $V'$, then save $V_2$.

V' = intersectEdge(V1, V2); outPoly[outCount++] = V'; outPoly[outCount++] = V2;

Boundary Intersection Equations

Given directed line segment from $V_1(x_1, y_1)$ to $V_2(x_2, y_2)$ with $\Delta x = x_2 - x_1$ and $\Delta y = y_2 - y_1$:

Clipping Boundary Fixed Coordinate Calculated Intersection Coordinate
Left Edge ($x = X_{min}$) $x_{int} = X_{min}$ $y_{int} = y_1 + \Delta y \cdot \frac{X_{min} - x_1}{\Delta x}$
Right Edge ($x = X_{max}$) $x_{int} = X_{max}$ $y_{int} = y_1 + \Delta y \cdot \frac{X_{max} - x_1}{\Delta x}$
Bottom Edge ($y = Y_{min}$) $y_{int} = Y_{min}$ $x_{int} = x_1 + \Delta x \cdot \frac{Y_{min} - y_1}{\Delta y}$
Top Edge ($y = Y_{max}$) $y_{int} = Y_{max}$ $x_{int} = x_1 + \Delta x \cdot \frac{Y_{max} - y_1}{\Delta y}$

9. Comprehensive Algorithm Comparison

Algorithm Category Arithmetic Time Complexity Key Distinction
DDA Line Line Rasterization Floating-point additions $O(\max(\Delta x, \Delta y))$ Simple differential approach, requires rounding per step
Bresenham Line Line Rasterization Pure integer arithmetic $O(\max(\Delta x, \Delta y))$ Error accumulation term; highly optimal for hardware
Midpoint Line Line Rasterization Pure integer arithmetic $O(\max(\Delta x, \Delta y))$ Evaluates implicit equation at midpoints across all 6 slopes
Midpoint Circle Circle Rasterization Pure integer arithmetic $O(R)$ 8-way symmetric reflection computing only $45^\circ$ octant
Cohen-Sutherland Line Clipping Bitwise codes + Float math $O(1)$ amortized Fast trivial rejection/acceptance using 4-bit region outcodes
Sutherland-Hodgman Polygon Clipping Float intersections $O(V \cdot E_{win})$ Sequential 4-stage pipeline producing closed clipped polygons
